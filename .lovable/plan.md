# Ускорение блока «02 — Проекты»

Сейчас в сетке проектов 17 карточек, и каждая картинка грузится сразу (`loading="eager"`), в полном «каталожном» размере JPEG. Все 52 фото хранятся на CDN только в одном тяжёлом варианте. Отсюда долгое открытие страницы.

## Что сделаем

1. **Лёгкие превью для карточек**
   Из каждого исходного фото создадим уменьшенную копию в формате WebP (ширина ~800 px, качество ~78) и загрузим её на CDN отдельным файлом. Карточка в сетке будет показывать превью, а полноразмерное фото откроется только внутри проекта и в полноэкранном просмотре. Ожидаемая экономия — примерно в 5–8 раз по весу первого экрана.

2. **Ленивая загрузка**
   Все фото проектов, кроме первых видимых карточек, получают `loading="lazy"` и `decoding="async"`. Первые 3 карточки остаются приоритетными, чтобы блок не «мигал» при скролле.

3. **Стабильная вёрстка без скачков**
   Каждому `img` добавим `width`/`height` (по пропорции контейнера) и `sizes`, чтобы браузер выбирал корректный масштаб и не пересчитывал layout.

4. **Фото внутри карточки проекта — только по требованию**
   Галерея внутри модального окна уже рендерится условно; дополнительно миниатюры галереи переводим на WebP-превью, а полный JPEG подгружается лишь при открытии фото на весь экран.

5. **Плавное появление**
   Лёгкий fade-in при загрузке изображения вместо серого блока — визуальный стиль сайта не меняется.

## Технические детали

- Скрипт на Python/PIL сгенерирует `*_thumb.webp` из уже отретушированных исходников; загрузка через `lovable-assets`, пойнтеры лягут в `src/assets/proj/`.
- `src/data/projects.ts`: у каждого проекта появится поле `thumbs: string[]` рядом с `photos`.
- `src/routes/index.tsx` (компонент `Portfolio`): сетка использует `thumbs`, модальное окно — `thumbs` для миниатюр и `photos` для полноэкранного просмотра; правки атрибутов `loading`/`decoding`/`sizes`.
- Фирменный стиль, тексты, структура блоков не меняются.
